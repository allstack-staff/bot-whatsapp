01 Comece por aqui

Em qualquer grupo ou no privado, mande:

$ajudaqualquer pessoa

O bot responde na hora com os comandos mais usados e o link pra essa página. Não precisa ser admin de nada pra usar esse.

Não passa por isAuthorized() de propósito — é o único comando sem checagem de permissão, já que é o ponto de entrada pra quem ainda não está no grupo de admins.

Exemplo: $ajuda → o bot responde com os comandos principais e o link dessa página.

02 Quem pode dar ordem ao bot

Pra usar os comandos de moderação, você precisa das duas coisas ao mesmo tempo:

  1. Ser admin do grupo onde você digitou o comando.
  2. Estar dentro do grupo de administração da comunidade (o grupo que foi registrado com $home).

Faltando qualquer um dos dois, o bot recusa e explica qual dos dois tá faltando.

Verificado em MessageHandler.isAuthorized(): checa admin do grupo atual via findParticipant(metadata, senderRaw) + isGroupAdmin(), depois varre os JIDs em AdminService.getAdminGroups() buscando o remetente (resolvido por PN e pela forma crua) em cada um via findParticipant. As duas checagens são obrigatórias — nenhuma supre a outra.

Não reintroduza comparação de string crua entre JIDs. Desde a migração do WhatsApp pra @lid, comparar id.split('@')[0] direto quebra silenciosamente. Use sempre resolvePnJid/findParticipant de utils/jid.ts.

03 Comandos essenciais

O bot reage na hora em toda mensagem com $: ✅ se reconheceu o comando, ❌ se não existe esse comando. Alguns comandos trocam a ✅ por uma reação mais específica ao terminar (ex: ⚠️ no $advertir). Quando uma ação automática falha (remover alguém, reverter descrição, aplicar logo, etc.), o aviso no grupo de admins vem com "reaja com 🔁 pra tentar de novo" — reagir com 🔁 nessa mensagem específica faz o bot tentar de novo, sem precisar de comando.

handleCommand reage ✅ assim que encontra um handler no mapa de comandos (antes de rodar — é só confirmação de reconhecimento, não de sucesso) e ❌ quando não encontra. Handlers específicos podem reagir de novo depois, substituindo a reação. Ações automáticas que falham chamam sendRetryableLog, que registra a ação em retryableActions (Map em memória, chave = id da mensagem) — uma reação 🔁 em handleReaction dispara runRetryable de novo com a mesma ação.

$homeadmin

Roda uma vez, dentro do grupo de administração, pra registrar ele como tal. Todo log de banimento cai ali. Se esse grupo for de uma Community do WhatsApp, o bot detecta sozinho qual é — ações em massa ficam restritas só a ela.

Upsert em AdminService.registerGroup(jid) → tabela AdminGroup. Se metadata.linkedParent existir, grava também em AdminGroup.communityJid — é isso que getCommunityGroupIds() lê primeiro (com COMMUNITY_JID do .env como fallback). Não precisa rodar de novo depois de trocar o número do bot — o registro não depende do número, mas rode de novo se trocar de grupo de admins ou de Community.

$home Exemplo: $home → ✅ Grupo registrado como admin/log. 🏘️ Community detectada...
$banadmin

Marque a pessoa ou responda a mensagem dela. Diz o tipo, opcionalmente uma duração (só pra temporário) e o motivo — todos opcionais. Motivo com várias palavras não precisa de aspas.

Resolve o alvo via getTargetJid (menção ou contextInfo.participant) → resolvePnJid → upsert em BannedUser. Bloqueia se o alvo for admin do grupo. O token logo após o tipo é testado contra parseDurationMs (^\d+[dhms]$) — se bater, vira a duração; senão, cai no motivo, que default é 7 dias. Remoção imediata: no grupo atual pra PERMANENTE/TEMPORARIO; em todos os grupos via groupFetchAllParticipating() pra COMUNIDADE, com humanBulkActionDelay() entre cada remoção.

$ban @user [permanente|temporario|comunidade] [duracao] [motivo] Exemplo: $ban @5541999999999 permanente flood · $ban @5541999999999 temporario 1m teste
$unbanadmin

Marque a pessoa, responda uma mensagem antiga dela (funciona mesmo se ela já saiu do grupo), ou digite o número completo. Também readiciona ela automaticamente aos grupos de onde foi removida. Motivo é obrigatório, exceto pra admin de comunidade.

Mesma resolução de alvo do $ban; se não vier menção/reply, cai pro fallback de número cru (args[0].replace(/\D/g, '')). Remove todos os registros daquele userJid, em qualquer grupo, independente do tipo — e chama tryReAddToGroup (mesmo helper do reAddExpiredBans) pra cada grupo afetado: todos os da comunidade se algum ban era COMUNIDADE, senão só o groupJid do registro. Sem motivo, exige isAdminOfAdminGroup (admin do grupo de admins, não só membro).

$unban @user [motivo] Exemplo: $unban 5541995850310 reavaliado, sem novas violações
$bansadmin

Lista quem está banido agora, com o motivo e (quando o bot souber) o nome público da pessoa.

BanService.getBans(), ordenado por createdAt desc. displayName é capturado de participant.notify no momento do $ban — bans anteriores a essa mudança não têm retroativamente.

$bans Exemplo: $bans → 📋 Usuários Banidos (2)...
$baneditadmin

Muda o tipo de um banimento já existente, ou quanto tempo falta pra expirar.

updateBanType / updateExpiresAt em BanService, escopados por [userJid, groupJid].

$banedit @user tipo comunidade $banedit @user tempo 7d Exemplo: $banedit @5541999999999 tempo 7d
$clearadmin

Apaga os comandos digitados pro bot e as respostas dele nesse grupo — deixa tudo limpo, inclusive o próprio $clear.

Rastro em memória por grupo (groupMessageLog), populado em trackGroupMessage a cada mensagem enviada/recebida. Apaga via sendMessage(jid, { delete: key }) — exige o bot ser admin do grupo pra apagar mensagem de terceiros. Não sobrevive a um restart (é intencional).

$clear Exemplo: $clear → apaga tudo que foi trocado com o bot nesse grupo, incluindo o próprio comando.
$statusadmin

Mostra o número conectado e quantos banimentos existem. Útil pra confirmar que uma troca de número deu certo.

Lê sock.user.id, AdminService.getAdminGroups() e BanService.getBans(). Nenhuma dessas fontes depende do número atual da sessão.

$status Exemplo: $status → Número conectado: 555181061198...
$advertiradmin

Dá uma advertência a alguém — marque ou responda a mensagem dela. 3 ou mais no mesmo mês banem a pessoa automaticamente, escalonando por reincidência nesse grupo: 1ª vez 7 dias, 2ª vez 30 dias, 3ª vez em diante permanente (com aviso pros admins avaliarem se vira banimento de comunidade).

WarningService.issue() grava em Warning; countThisMonth conta desde o dia 1 do mês corrente. Ao atingir 3, applyWarningPunishment chama incrementPunishmentCount (tabela WarningPunishmentHistory) pra decidir o tier, e o mesmo BanService.ban() do $ban. A moderação por IA usa o mesmo issue()/applyWarningPunishment. Alvo resolvido via getTargetJid (menção ou reply), mesmo padrão do $ban.

$advertir @user [motivo] Exemplo: $advertir @5541999999999 flood → ⚠️ advertido (2/3 esse mês).
$regrasadmin

Aplica o link das regras da comunidade na descrição de todos os grupos que o bot administra, na próxima linha livre — pula quem já tem o link.

Ação em massa: uma groupUpdateDescription por grupo, com humanBulkActionDelay() entre cada uma. Marca cada escrita em recentSelfDescriptionUpdate pra não disparar o fluxo de votação de mudança de descrição.

$regras Exemplo: $regras → ✅ Link das regras aplicado em 6 grupo(s) (2 já tinham).
$gruposadmin

Lista os grupos da comunidade com um número curto — use esse número no $responsavel ou $assumir pra não precisar entrar no grupo alvo.

CommunityGroupService.upsertSeen atualiza o registro a cada chamada (nome/novos grupos), depois lista via getAll() filtrado pelos IDs de getCommunityGroupIds().

$grupos Exemplo: $grupos → 1. SysAdmins, 2. DevOps, ...
$assumirgrupo de admins

Quem já está no grupo de administração pode virar admin de qualquer grupo da comunidade na hora — sem precisar que outro admin faça isso manualmente pelo WhatsApp.

Exige só isMemberOfAdminGroup (não isGroupAdmin do grupo atual — é isso que o comando resolve). Sem args[0] numérico, usa o grupo atual; com número, resolve via CommunityGroupService.getJidByShortId. Promove via groupParticipantsUpdate(..., 'promote').

$assumir [id] Exemplo: $assumir (no grupo) ou $assumir 3 (do grupo de admins) → ✅ Você agora é admin do grupo *Nome*.
$responsaveladmin

Marca um admin como responsável por um grupo — o bot usa isso pra saber quem avisar quando há pendência (tipo pedido de entrada) e quem anunciar numa promoção. Sem número, usa o grupo atual; com um número (veja $grupos), dá pra rodar direto do grupo de admins.

AdminResponsibilityService.assign(adminJid, groupJid). Se args[0] for numérico, resolve o groupJid via CommunityGroupService.getJidByShortId em vez do grupo atual. Usado por handleGroupJoinRequest pra rotear avisos de pedido pendente.

$responsavel [id] @admin Exemplo: $responsavel @5541988887777 (no grupo) ou $responsavel 3 @5541988887777 (do grupo de admins) → ✅ agora é responsável pelo grupo *Nome*.
$promoveradmin

Promove alguém a admin do grupo, marca como responsável por ele, e anuncia a promoção — inclusive no grupo "Avisos" da Community, achado sozinho pelo bot.

groupParticipantsUpdate(..., 'promote') + AdminResponsibilityService.assign() + anúncio via findCommunityAnnounceGroupJid() (procura isCommunityAnnounce nos metadados).

$promover @user Exemplo: $promover @5541988887777 → 🎉 ...promovido(a)... (no grupo e no "Avisos")

04 Tipos de banimento

Pense nos três tipos como três "tamanhos" de banimento:

Permanente

Fica banido daquele grupo específico pra sempre.

escopo: groupJid exato · sem expiresAt
Temporário

Fica banido daquele grupo por um tempo (7 dias por padrão).

escopo: groupJid exato · expiresAt = agora + 7d
Comunidade

Fica banido de todos os grupos que o bot administra.

escopo: qualquer groupJid · getActiveBan ignora groupJid

"Comunidade" não é a feature nativa Community do WhatsApp (linkedParent) — é uma convenção própria do bot: qualquer grupo em que o alvo esteja e o bot administre. Ver getActiveBan() em banService.ts.

Se a pessoa tentar entrar de novo em qualquer lugar onde o banimento vale, o bot remove sozinho e avisa no grupo de admins. Em grupos com aprovação de admin pra novos membros, o pedido de entrada é rejeitado na hora — a pessoa nunca chega a entrar.

Evento group.join-request (não confundir com group-participants.update, que é pós-entrada): se getActiveBan encontrar banimento válido pro id do grupo, chama groupRequestParticipantsUpdate(id, [participant], 'reject') antes da pessoa virar membro.

05 O que acontece sem nenhum comando

Aprovação de mudança de descrição

Se um admin edita a descrição de um grupo pelo próprio WhatsApp, o bot avisa no grupo de admins pedindo votação (✅/❌). Maioria rejeita → volta a versão antiga e o grupo fica travado 7 dias.

Detectado via evento groups.update, comparado contra descriptionCache. Voto por messages.reaction, tabulado em descriptionVotes (memória). Rejeição grava GroupDescriptionLock.frozenDescription e qualquer edição durante a trava é revertida na hora.

Moderação por IA (a cada hora)

Se houve mensagem nova em algum grupo desde a última checagem, o bot avalia contra as regras usando o Gemini (grátis). Violação grave = banimento de comunidade direto; o resto = advertência comum. Sem chave de API configurada, isso simplesmente não roda.

pendingModerationMessages (buffer em memória, por grupo) — vazio, nem chama a IA. AiModerationService.evaluateMessages() pede JSON estrito ao Gemini; qualquer erro de rede/parse é tratado como "sem violação" (falha fechada).

Readição ao expirar um banimento temporário (a cada 5 min)

Quando um banimento temporario vence, o bot tenta readicionar a pessoa ao grupo sozinho, sem esperar ela pedir. Sempre avisa no grupo de admins: ✅ se conseguiu, ⚠️ com o link de convite se não conseguiu (privacidade da pessoa não permite ser adicionada direto).

BanService.getExpiredTemporaryBans() a cada BAN_EXPIRY_TICK_MS (5min). Remove o registro de qualquer forma (o prazo já passou); a readição via tryReAddToGroup (groupParticipantsUpdate(..., 'add')) é só cortesia por cima disso. Status ≠ '200' → busca groupInviteCode e inclui o link no aviso de falha.

Desfazer punição automática (reação ou reply no aviso)

Todo banimento automático (IA ou acúmulo de advertências) vem com opção de desfazer no próprio aviso, no grupo de admins: reaja ❌ pra desfazer sem motivo, ou responda com um texto pra desfazer com motivo registrado. Remove o banimento, readiciona a pessoa e deixa claro que foi revisão humana.

AutomatedPunishment grava toda punição automática com o messageId do aviso. handleReaction checa esse messageId primeiro (antes da votação de descrição) pra reação ❌; handleMessage checa contextInfo.stanzaId de replies não-comando contra a mesma tabela pra desfazer com motivo. Ambos chamam revertAutomatedPunishment: unban + tryReAddToGroup + log explicando que foi revertido por revisão humana.

06 Se o número do bot for perdido ou banido

Fica tranquilo — nenhum banimento ou configuração se perde. O bot só precisa de um número novo pra voltar a funcionar.

  1. Escaneie o QR code com o número novo.Apague SESSION_PATH (padrão ./auth) e suba o processo de novo — um QR novo aparece.
  2. Adicione o número novo em cada grupo e promova ele a admin — isso é manual, o WhatsApp não deixa transferir esse cargo entre números.Sem isso, groupParticipantsUpdate e a leitura de groupMetadata falham por falta de permissão.
  3. Rode $status pra confirmar: número certo, grupos de admin registrados e contagem de banimentos batendo com o esperado.

Nada em AdminGroup/BannedUser referencia o número do próprio bot — só JIDs de membros e grupos. É por isso que a troca não perde estado.

07 Migração de hospedagem sem perda de dados

Diferente da troca de número (que assume um número novo e QR novo), migração é mover o bot pra outro servidor mantendo o mesmo número — sem re-escanear nada.

  1. Pare o processo no servidor antigo (pm2 stop bot-whatsapp).
  2. Copie a pasta inteira do projeto pro servidor novo — os dois diretórios que realmente importam são auth/ (sessão do WhatsApp) e prisma/dev.db (todo o estado: banimentos, grupos de admin, advertências). Ambos ficam fora do git (.gitignore), então um git clone sozinho não traz esses dois.
  3. No servidor novo: npm install, npx prisma generate, compile (tsc), suba com pm2 start npm --name bot-whatsapp -- run start.
  4. Como a pasta auth/ veio junto, o Baileys reconecta a mesma sessão automaticamente — sem QR code.
Nunca rode o bot em dois lugares ao mesmo tempo com a mesma auth/. O WhatsApp permite só uma conexão ativa por sessão — a mais nova derruba a mais antiga (connectionReplaced). Desligue o antigo antes de subir o novo.

08 Arquitetura

TypeScript (commonjs) sobre Baileys — protocolo WhatsApp Web, não a API oficial da Meta. Persistência via Prisma + better-sqlite3, arquivo único.

src/infra/bot/ handlers/messageHandler.ts  // dispatch de comandos services/banService.ts      // CRUD de banimentos services/adminService.ts     // CRUD de grupos de admin utils/jid.ts             // resolução de identidade (LID) utils/delay.ts          // pausas anti-detecção de bot

Resolução de identidade (LID)

Desde meados de 2026 o WhatsApp identifica participantes por um ID opaco (@lid), sem relação com o número de telefone — a mesma pessoa pode aparecer ora como @lid, ora como @s.whatsapp.net.

// utils/jid.ts findParticipant(metadata, jid) // acha por id, lid ou phoneNumber resolvePnJid(sock, jid, metadata?) // 1. tenta pelo phoneNumber já nos metadados do grupo // 2. cai pra sock.signalRepository.lidMapping (store oficial do Baileys)

Todo banimento é gravado com o JID de telefone já resolvido — por isso o $unban funciona independente de o WhatsApp endereçar a pessoa por @lid ou por número naquele momento.

Anti-detecção de bot

Baileys é biblioteca não-oficial; a Meta investe em detectar padrões automatizados. Duas pausas humanizadas mitigam o padrão mais óbvio (timing robótico):

OndeFunçãoFaixa
antes de qualquer respostahumanReplyDelay()800–2000ms
entre remoções em massahumanBulkActionDelay()1500–4000ms
Isso reduz risco, não elimina. Baileys continua sendo cliente não-oficial. Número virtual/VOIP falha direto na verificação do WhatsApp em 2026 — use sempre chip/eSIM de operadora real.
